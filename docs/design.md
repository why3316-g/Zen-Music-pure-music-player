## Problem Statement

自用的 Windows 桌面音乐播放器。现有播放器要么太重（网易云、QQ 音乐），要么太丑（Windows Media Player），要么没有视觉冲击力。想要一个功能克制、但界面和播放效果极致漂亮的播放器，支持音乐+视频播放，并且可以切换多种视觉风格。

## What Makes This Cool

1. **三种主题风格一键切换**：苹果极简风、Arc 现代科技风、黑胶唱片复古风——共享同一套播放逻辑，纯粹 CSS 层切换
2. **音乐可视化**：Web Audio API 频谱分析 + Canvas 渲染，波形/粒子/频谱条随音乐实时律动
3. **黑胶唱片动画**：专辑封面作为唱片，播放时旋转，唱臂摆动，网易云那种经典感
4. **在线音乐搜索**：接入免费音乐源，搜索后直接播放或下载到本地
5. **定时暂停**：睡前听歌自动停

## Constraints

- Windows 10 桌面应用（FLAC 支持依赖系统编解码器，Windows 10 1709+ 原生支持）
- Electron + Vue 3
- 个人使用，不考虑多用户/账号系统
- 在线音乐源用非官方 API（免费但不稳定，需要降级策略）
- 包体大小不敏感（Electron ~150MB 可接受）
- 播放列表和设置默认持久化（`electron-store`）

## Premises

1. 主题系统是核心架构——不同视觉风格共享播放逻辑，只切换 CSS/布局层
2. 音频和视频用同一个播放引擎——HTMLMediaElement（`<video>` 标签统一处理音频和视频）
3. 音乐可视化是"科技感"的核心——Web Audio API + Canvas/GL 实现
4. 功能范围：播放控制、循环模式、歌词、定时暂停、播放列表、本地导入、在线搜索、可视化
5. 在线音乐用非官方 API，需要做好"搜索不可用"时的降级体验

## Approaches Considered

### Approach A: Minimal Viable
Electron + React + 基础 CSS 主题 + HTML5 播放 + 基础频谱。3-5 天。功能有限，视觉效果平庸。

### Approach B: Ideal Architecture (chosen)
Electron + Vue 3 + 主题插件系统 + 增强可视化 + 开源音乐 API。1-2 周。全面覆盖需求。

### Approach C: Wails + Go
包体小 10 倍，但生态不成熟，技术风险高。2-3 周。

## Recommended Approach: Approach B

### 核心模块设计

#### 1. 播放引擎

```
audio-engine.js
├── AudioContext（Web Audio API）
│   ├── AnalyserNode → 频谱数据（FFT）→ 传给 Visualizer
│   └── GainNode → 音量控制
├── HTMLMediaElement（<audio>/<video>）
│   ├── 本地文件：file:// 协议
│   └── 在线流：URL 直接播放
└── 状态管理（Pinia）
    ├── currentTrack
    ├── isPlaying
    ├── currentTime / duration
    ├── playMode: 'single' | 'loop' | 'shuffle'
    └── volume
```

音频和视频共用 HTML5 `<video>` 标签（它也能播音频）。纯音频时隐藏视频画面，显示可视化效果。播放视频时切换到视频模式。

**Web Audio API CORS 解决方案（/plan-eng-review 审查结论）：**
在 Electron 主进程注册自定义协议 `app://`，本地文件通过该协议加载。这样 `createMediaElementSource()` 直接工作，一条管线同时负责播放和可视化，无 CORS 问题，无内存翻倍，无需手动同步播放位置。

```
// electron/main.ts
protocol.registerSchemesAsPrivileged([
  { scheme: 'app', privileges: { bypassCSP: true, stream: true, supportFetchAPI: true } }
])
// 渲染进程中：<video src="app://local/C:/Music/song.mp3">
// createMediaElementSource(videoEl) → AnalyserNode → 频谱数据
```

注意：首次播放时 AudioContext 可能处于 `suspended` 状态，需要在用户交互时调用 `audioContext.resume()`。

#### 2. 主题系统

每个主题是一个文件夹，包含：
- `theme.json`：主题元数据（名称、描述、预览颜色、版本）
- `styles.css`：CSS 自定义属性覆盖（颜色、圆角、阴影、字体、动画）
- 可选的 Vue 组件覆盖（如黑胶主题需要 `VinylDisc.vue`）

主题加载机制：
1. 应用启动时扫描 `themes/` 目录，读取每个主题的 `theme.json`
2. 所有主题定义同一套 CSS 变量名（`--bg-primary`、`--accent` 等）
3. 切换主题时：设置 `<html data-theme="apple|arc|vinyl">`，各主题的 CSS 通过 `[data-theme="xxx"]` 选择器覆盖变量值
4. 黑胶主题的 `VinylDisc.vue` 通过 `v-if="currentTheme === 'vinyl'"` 条件渲染，替代默认的封面组件
5. CSS Variables 控制核心视觉：
   ```css
   :root {
     --bg-primary: #0a0a0a;
     --bg-secondary: #1a1a1a;
     --text-primary: #ffffff;
     --accent: #1db954;
     --player-height: 80px;
     --radius: 12px;
     --glass-blur: 20px;
     --disc-size: 280px;
   }
   ```

#### 3. 三种主题风格定义

**Apple 极简风**
- 大面积留白，圆角卡片
- 大号专辑封面居中
- 底部播放条，毛玻璃效果
- 颜色：白底/浅灰、黑色文字、彩色强调
- 可视化：柔和的波形线条

**Arc 现代科技风**
- 深色背景（#0a0a0a → #1a1a1a 渐变）
- 霓虹渐变强调色（蓝紫/青色）
- 边框发光效果
- 可视化：锐利的频谱柱 + 粒子效果
- 侧边栏导航

**黑胶唱片风**
- 温暖的深木色背景
- 中央大唱片（专辑封面），播放时旋转
- 唱臂从右侧摆入，暂停时抬起
- 金色/铜色强调
- 可视化：唱片沟槽纹理 + 暖色调光晕

#### 4. 可视化系统 (Visualizer.vue)

```javascript
// V1: 频谱柱状图（最经典，实现最简单）
// 后续可扩展 waveform 和 particles 模式
const MODE = 'spectrum'
```

- `requestAnimationFrame` 循环
- 从 `AnalyserNode.getByteFrequencyData()` 取频谱数据
- Canvas 2D 渲染（性能足够，不需要 WebGL）
- 主题通过 CSS Variables 控制可视化颜色和风格
- 黑胶主题额外要求：唱片旋转用 `transform: rotate()` + `will-change: transform` 确保 GPU 加速，避免用 `left/top` 触发重排
- 组件 `onUnmounted` 时 `cancelAnimationFrame(rafId)`，页面不可见时暂停渲染

#### 5. 在线音乐搜索

策略：多源降级。

```javascript
// music-api.js
const SOURCES = [
  { name: 'netease', type: 'self-hosted', repo: 'https://github.com/Binaryify/NeteaseCloudMusicApi' },
  { name: 'kugou',   type: 'unofficial',  note: '酷狗非官方 API' },
  { name: 'kuwo',    type: 'unofficial',  note: '酷我非官方 API' },
]

async function search(keyword) {
  for (const source of SOURCES) {
    try {
      const results = await fetchFromSource(source, keyword)
      if (results.length > 0) return results
    } catch (e) {
      console.warn(`${source.name} failed, trying next...`)
      continue
    }
  }
  return [] // 全部失败，显示"搜索暂不可用"
}
```

音乐源候选：
- `NeteaseCloudMusicApi`（GitHub 开源，需自己部署，`npm install` 后跑一个本地服务即可）
- 酷狗/酷我音乐 API（非官方，免费但不稳定）
- **定位为实验性功能**：UI 上放在侧边栏次要位置，搜索不可用时灰色提示"搜索暂不可用，请添加本地文件"
- 降级策略：任一源失败自动切换下一个，全部失败则隐藏搜索结果

搜索结果可以：
1. 直接在线播放（点击播放，流式加载）
2. 下载到本地（加入播放列表）

#### 7. 定时暂停

```
Timer.vue
├── 预设：15分钟 / 30分钟 / 45分钟 / 60分钟
├── 自定义时间
└── 到时间 → 渐弱音量（5秒） → 暂停
```

不做"定时关机"——那需要系统级权限，复杂且危险。定时暂停足够用。

#### 8. 系统集成

- **系统托盘**：最小化到托盘，右键菜单（播放/暂停、上一曲/下一曲、退出）
- **全局快捷键**：
  - `MediaPlayPause`：播放/暂停
  - `MediaNextTrack`：下一曲
  - `MediaPreviousTrack`：上一曲
  - `Ctrl+Shift+M`：迷你模式切换
- **迷你模式**（V2）：小窗口（320x80），只有播放控制和进度条，悬浮在最前面。`Ctrl+Shift+M` 切换，再次按或双击窗口切回
- **文件关联**：拖拽文件到窗口直接添加到播放列表

## Error Handling

- **文件不可用**（被删除/移动）：播放列表中标记为红色，自动跳到下一曲
- **不支持的格式**：弹出提示"不支持此格式"，不崩溃
- **在线播放网络断开**：缓冲中显示 loading 状态，超时 30 秒后提示"网络异常"，自动尝试下一曲
- **API 全部失败**：搜索按钮显示"暂不可用"，不影响本地播放
- **损坏的音频文件**：捕获解码错误，标记文件异常，跳到下一曲

## What I noticed about how you think

- 你说"最好有多种风格"的时候，不是在提需求，而是在想象打开播放器时的那种满足感。你先想的是"它看起来多酷"，然后才是"它要做什么"。这是设计驱动的思维方式。
- 你说"在线搜索还是要的，影响不大吧"——你在追加功能时用的是"影响不大"来评估成本，而不是"这个必须要有"。这说明你在意的不是功能本身，而是最终体验的完整性。这也解释了你为什么说"不行就隐藏"——你愿意为功能做减法。
